# PDF 信息保留改进验证（2026-11-02）

## 交付与边界

完成通用文档结构层、覆盖报告、结构化表格行、同列单位核验、本地原生文字补充和发布覆盖提示。没有接入新的云解析服务、OCR 模型或视觉模型，没有修改任何汽车领域知识。第一窗口没有读取汽车原始文档或 benchmark。

这是一轮信息保留与安全门禁改进，不是完整多模态 PDF 验收，也没有产生汽车问答准确率。

## 实现

- 每个解析版本分别保存不可变的原始 JSON、文档单元及覆盖报告。单元包含文字、表格、图片、公式等类型、位置、来源和提取状态。
- 图片即使有标题也会报告尚未做视觉分析。空公式、缺失页和不支持的合并单元格不能静默当成完整提取。
- 保留上/下标样式，以 `^{...}`、`_{...}` 表达。空公式区域可通过本地 pypdf 补充原生可读字符，仍不宣称数学结构已经识别。
- 密集矩阵表格按完整表头与数据行形成独立证据块。单位只在核验时与同列标题和当前领域声明的单位匹配；不会把 `(maximum)` 等注释拼成虚假的量值。
- 原生布局可补充候选表格；逐个去重，不因同页已有一张表就跳过其他表。布局推断明确标为 `requires_review`，相应事实保留为待审核候选，不能自动发布。
- 未审核的派生行不进入原文检索索引，防止绕过候选门禁。原始数字文字仍按原路径保留；已确认事实按既有机制引用证据。
- 新增 producer-only MCP `inspect_source_parse`。发布 manifest 带覆盖摘要，Wiki 带解析范围提示；不导出 producer 的完整文档单元。
- pipeline 按最终选择记录的证据统计表格行引用情况，始终声明不代表语义完整性。表格行超预算显式失败，不能被字符切块截断。
- 解析缓存绑定当前 parser_version，保留旧解析和旧发布。009 迁移只给 parse_versions 增加两个 JSONB 列，不新增行业表、关系类型或图类型。
- 模型请求将条件名限定为第二窗口声明的领域条件，事实来源类型限定为原有四种；不能表达的范围可进入 extraction_notes，保留在批次报告。

## 分段耗时与 Token

最后一次提取使用已缓存的当前版本解析：读取解析并加载块 0.012 秒；DeepSeek 提取及修复 11.749 秒；模型支持复核 2.271 秒；无 embedding 构建 0.071 秒。首次当前版本本地解析及落库另一次测量为 1.127 秒，不能把缓存读取时间当作 PDF 解析性能。

最后一次提取共 8870 tokens，复核 3604 tokens，合计 12474 tokens。包括本轮诊断修复调用，不等于付费账单或每份 PDF 的成本承诺。各次试跑证据分别保存在 improved-result-v2.json、improved-result-v3-provenance-error.json、improved-result-v3-condition-error.json、improved-result-v4-before-review-gate.json 等；最终以 final-result.json 为准。

final-result.json 记录最后提取、复核、重建 ID、分段耗时和原文索引门禁检查。最终重建再次确认未审核派生行不在原文索引中，覆盖报告随构建固定。此实验关闭 embedding，不测试问答服务，不冒充完整发布/检索 E2E。
