# 共用知识库框架验证（2026-11-02）

本轮只使用两份独立合成设备资料。第一窗口没有读取汽车原始资料或新的独立评测题目/答案；本报告不代表汽车评测通过或多领域通用性成立。

## 结果

- 产品init-kb在不调用Codex/LLM时创建空数据库知识库及单个外部知识库根目录。
- 两个真实原生Codex以同一目录为cwd，通过不同鉴权MCP分别建库、消费。产品管理后台服务与worker，客户端无后台数据库/签名/DeepSeek密钥。
- producer用公开start_pipeline处理两来源，产品自动分批、抽取、结构/词面核验、模型语义支持复核、构建及发布；没有人工补数据库或手写Wiki。最终7条记录、3页Wiki，固定发布版`dc461c84-5ebd-442d-a3f7-6dbae13d438d`。
- consumer验证实际两条图关系、逐边原文、Wiki目录及3页正文；F01后台retrieve返回20℃额定功率10.25 W，F04对30℃功率/变化比例表示证据不足。两题后台API无错误。
- F01实际后台8710.592ms、8203 token、3轮；F04为12266.812ms、13927 token、5轮。两条图查询是直接MCP验证，不能把它们算成后台retrieve的通过率。构建内部逐阶段耗时本轮未全部采集，不填估计值。
- 116项自动检查通过，覆盖共享根目录、角色权限、外部结果目录、模型review失败后的checkpoint恢复、全产品指纹变化拒绝恢复、来源撤回、对象引用闭包、发布失败不暴露文件、旧构建重试和rollback指针一致性等。

## 本轮修复与保留失败

首次真实启动与构建曾被回环请求走代理影响。已修复角色客户端/后台的NO_PROXY和本地HTTP直连，保留失败任务与旧运行日志；因产品版本变化创建新Pipeline任务，不静默混用旧批次。

代码审查还发现并修复：客户端继承后台环境秘密、未提交文件提前暴露、版本摘要覆盖不全，以及旧构建重试把文件指针退回旧版。发布按KB串行，以数据库为权威同步文件；跨数据库/文件不是原子事务，异常后通过幂等重试恢复。

## 第三窗口行为纠正

早期烟测曾由C1在第三窗口提示中安排产品/domain canary试写，两次均被拒绝、没有生成文件。这个安排已撤销，不是第三窗口的正常任务。今后第三窗口只检索、问答、评测和写指定结果目录，权限负向测试仅由C1在合成夹具执行。

纠正后的真实第三窗口复核只调用describe_kb、list_wiki_pages与读取index.md，并向配置结果目录写报告，没有再试写产品/知识资产。该次客户端初始查找元数据时使用目录遍历、触及受保护目录并被OS拒绝的行为偏差已记录；未读取其中正文。指南已进一步明确从已知元数据入口直接开始、禁止目录树扫描。不能把OS拦截视为Agent行为已经完美遵守。

## 当前交付与限制

正式汽车知识库根目录为`gsm-automotive-kb/`，仍为空库。结果配置为外部`gsm-automotive-results/`，建库者不可读；`gsm-runtime-data/`只管理产品运行，实验状态在`gsm-iteration-control/`。第一窗口对原始资料/独立评测的禁止读取是开发规范，不宣称已接管当前Codex宿主的所有文件权限。

合成角色记录、完整API trace、交接与结果保存在外部`gsm-iteration-control/framework-001/`，不进入产品知识语料。旧日志及失败不覆盖。严格客户端OS启动器当前验证macOS，不自动降级；需要使用指定启动器，仅打开文件夹不等于隔离。

Wiki当前按领域类型生成主题页并分页、附目录/相关主题与证据，是确定性的有据文档；不是LLM长篇自由写作。语义支持复核是模型检查，不是专家金标准。部分对象显示名可能回落到稳定身份ID，这是已保留的展示限制。更广泛身份别名对齐、语义完整性与正式领域质量仍需独立评测。
