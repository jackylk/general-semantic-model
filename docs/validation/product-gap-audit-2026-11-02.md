# 产品能力差距检查（2026-11-02）

本次对照原始任务书、v64 PPT 实际页面、公开合同及实现。代码检查基线为 `ac73a98`；下文标为“已修正”的目录默认值与初始化限制是本次变更，其余缺口尚未修复。原型及汽车实验不算最终验收通过。

## 第一窗口、第二窗口的职责

第一窗口开发通用的文档加工、抽取与核验、主题规划、多页 Wiki/Catalog 生成、索引、版本发布、检索、评估和反馈处理。第二窗口调用产品能力，配置领域词汇、资料范围、用途、主题偏好及业务确认；不能改产品代码、固定 Schema、内部表或用旁路脚本替代缺失的产品功能。第三窗口只消费发布版，记录问答与反馈。

第二窗口可以用 Codex 编排公开工具、编写领域资产，但产品应承担可复现的分批、覆盖统计、恢复、校验与一致发布，不应把正确性依赖在某次会话自创的循环上。

## 本次已落实的目录分离

- 产品仓库仅用于第一窗口开发。`init-workspaces` 现在拒绝产品目录内部的工作区，包括通过符号链接进入的路径。
- 默认文档收件入口为空，不猜资料位置；默认原件存储移到用户数据目录，`.env.example` 给出产品目录外的配置示例。
- 真实汽车实验搬到独立外部目录，两个角色的文档、领域资产、测试结果、私有控制资料与会话状态不再放在产品运行目录。旧产物原样归档，历史记录中的原路径不改写。
- 汽车验证启动器实际应用外层 macOS OS 沙箱，禁止两个角色读写产品、读私有基准及另一角色目录；只允许写本角色工作区与会话目录。第三窗口无建库、核验、发布工具。
- 普通 `init-workspaces` 入口当前仍是原生 workspace-write 启动器，不能把汽车实验的额外 OS 读取隔离当作普通客户端已具备的能力。直接打开文件夹本身不构成 OS 隔离；此次强隔离限于指定汽车启动器和自动测试入口。
- 原件按知识库 UUID 分目录保存在外部存储，PG 保持知识库作用域与不可变发布版。知识库工作目录不等于 PG 的物理数据目录。

本次目录迁移和边界检查不等于修复以下产品缺陷，也不等于完成多页 Wiki。

## 受控复现

本次C1在两个新建合成测试知识库中运行，不修改已有汽车知识库，不调用LLM/Embedding。观察结果见 [product-gap-probes-2026-11-02.json](product-gap-probes-2026-11-02.json)。这些输出是缺陷复现，不是“验收通过”；现有94项测试没有覆盖这些失败场景。

1. 同一条“A连接B”引用，记录反向B→A：状态 verified、无 issues。
2. 仅发布该 relation：成功，发布集合里没有 object 记录。
3. 序号999、valid_from=not-a-date，引用序号001：仍 verified、无 issues。
4. 一条记录受两来源支持，撤回其中一个后新建发布：2个Wiki引用中1个读证据返回NOT_FOUND，新索引仍含1个撤回来源块。

目录分离另外完成了真实负向权限检查：只读MCP写操作、跨库、伪造引用、产品读写、跨角色读取均被拒绝，本角色目录可写。原生启动器还需实际会话烟测结果与边界结果一起保留，不以AGENTS文字替代。
